## Summary

**Problem:** The `refreshToken()` function in `session.ts` had a race condition where concurrent requests with the same refresh token would both read the valid row, both insert new tokens, and both revoke the old one, resulting in 2 active tokens instead of 1.

**Fix:** Wrapped the SELECT-INSERT-UPDATE operations in a PostgreSQL transaction with `SELECT ... FOR UPDATE` to lock the refresh token row during rotation. This ensures only one request can process a token at a time, making the operations atomic.

**Change in `session.ts`:** The function now uses `db.tx()` with `FOR UPDATE` on the SELECT query, keeping the exported function signature identical (`refreshToken(userId: string, oldToken: string): Promise<string>`) for backward compatibility.
